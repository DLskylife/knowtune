# KnowTune 使用说明书

本地知识库问答。文档进来，问答出去，每个结论都挂着能回查的引用。

这份文档只讲**怎么用、怎么看结果、出了问题怎么办**。设计取舍见
[ARCHITECTURE.md](ARCHITECTURE.md)，文件地图见 [PROJECT_MAP.md](PROJECT_MAP.md)。

---

## 1. 五分钟跑起来

```bash
cd sky_agent
.venv/Scripts/python.exe -m knowtune.cli serve --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。

启动后有三件事在后台做，都在 30 秒内完成，状态栏会逐项变绿：

| 后台任务 | 做什么 | 慢的后果 |
|---|---|---|
| 嵌入模型预热 | 读 92MB 的 bge-small-zh | 预热完之前不让提问（按钮禁用） |
| 向量矩阵加载 | 全部 chunk 的向量读进内存 | 同一条链路 |
| 精排预热 | 读 1.1GB 的 bge-reranker | 不预热的话第一次提问多等 7 秒 |

**首次提问前先看一眼左下角三行**：

```
● 索引就绪  28,020 chunk
  精排     bge-reranker-base
● 生成     siliconflow
```

- 第三行红点 = 生成后端没配好，提问只会返回引用不会返回答案。去「模型服务」页加端点。
- 精排显示「已关闭」时把鼠标停上去，会告诉你是全局关的还是这个库单独关的。
- 不想调云端、本机有 `.gguf` 的话，见 §11：一条命令装好 llama-server 就能离线跑。

## 2. 建库与导入

左侧「+」新建知识库。建库时选预设（通用 / 代码 / 长文档），预设只改检索参数，
**不碰拒答阈值**——那个数必须标定，不能预置。

拖文件进窗口即可，或：

```bash
.venv/Scripts/python.exe -m knowtune.cli ingest ./docs --kb 2
```

支持 PDF / Word / Excel / PPT / Markdown / 源码 / URL / 粘贴文本。超过 8MB
自动分片，断了可以续。

**分块只影响新导入或重建索引的文档。** 改完分块参数，界面会提示「需重建索引」，
点重索引才会对已有文档生效——不点的话提问拿到的还是旧块。

**文档可以换库，不用重新导入。** 知识库详情页每篇文档右侧的「移动」选目标库即可：
只改 `document.kb_id`，chunk、向量、引用编号全部原样保留，随后刷一次向量缓存
（`VectorStore` 那份 chunk → kb_id 内存掩码是加载时的快照，不刷会让 dense 路
继续按旧库过滤，表现成"文档明明在库里却搜不到"）。同一个源文件在目标库已有
一份时会被拒绝，不会静默覆盖。

当前三个库的规模：

| 库 | 文档 | 块 | 用途 |
|---|---|---|---|
| 维医知识库 (#2) | 26 | 322 | 前台「维医问答」、预问诊的主库 |
| 古籍知识库 (#4) | 5 | 1,120 | 前台「古籍问答」专用，五部中医古籍 |
| 临床药理（试导入）(#3) | 1 | 26,578 | OCR 链路验证，不进前台 |

前台站点可以给「古籍问答」单独绑一个库（站点配置里的 `classic_kb_id`）。没绑、
库被删了、或库里还没有 ready 文档，就退回老办法：在主库里按标题含「古籍」分。
两种模式下两边检索都各自只在自己的 `kb_id` 里找，古籍不会串进维医答案。

侧栏顶部那行「库名 + 多少篇文档 · 多少片段」跟着当前板块走：在「古籍问答」里报的
是古籍库自己的 5 篇 / 1,120 片段，不是两个库的合计。导航项右侧的计数带单位
（`26 篇`），预问诊那一栏写「不检索」，因为它不读知识库、只整理症状。

那行库名**按语言各配一份**：站点弹窗 →「界面文案 → 侧栏库名」管主语言，
「另一语言 → 侧栏库名」管右上角切过去的那套（中文站点常在这里填中文名）。
两处留空都回落到知识库本身的名字。前台只管显示，不改库表——后台知识库列表里
仍然是原名字。

**三个板块都能在站点弹窗里配。**「前台站点 → 模型与参数 → 板块」把左侧三个入口
摆在一起：每个都能改名（留空用界面语言的内置名字）、能单独关掉，维医和古籍还各自
绑定自己要检索的库。关掉的入口在站点上真的消失——导航里没有，直接打
`/previsit/api/...` 也只回 404，不是只藏一个按钮。三个全关会被拒绝保存：那是张空白页。

**切换板块会真的换内容。** 对话按板块分开存：在「维医问答」问完一段，点「古籍问答」
看到的是古籍自己那段对话（没有就显示欢迎页与古籍示例问题），切回来还是原来那段维医
记录。顶栏大标题、副标题、输入框占位、示例问题、侧栏库名与篇数、浏览器标签页标题
一起换——以前只有副标题在换，标题还挂着「维医知识问答」，看上去像没切过去。预问诊
不占问答会话：进去看症状采集，回来接着原来那段问诊记录。

预问诊**没有独立站点**，也没有独立页面：模型、轮次、知识图谱追问、语义召回、文案与
提示词都在站点卡上那颗「预问诊参数」里改，保存立即生效、不重启、不打断正在进行的
问诊。后台不再有 `/previsit/` 那一份副本，`knowtune previsit` 子命令也已删除。

**界面文案不在站点配置里改。** 标题、副标题、欢迎语、示例问题、免责声明统一在
「模型 → 提示词配置」的「界面文案 · 维吾尔语 / 中文」两个角色里维护，改完保存
立即生效、不用重启站点；每次保存前自动留快照，改坏了可以整体回滚。站点弹窗里
只保留「知识库显示名」——那个名字跟着绑定的库走，不属于站点文案。提示词里没
改过的字段回落到出厂默认（`instcfg.default_copy`），新建站点拿到的默认文案也
从同一处取。

## 3. 提问，然后读结果

一次回答底下有四个信号，它们回答四个不同的问题：

| 信号 | 回答的问题 | 怎么读 |
|---|---|---|
| **引用编号** `[1]` | 这句话的依据在哪条资料 | 点编号跳到原文；悬停看预览 |
| **引用覆盖率** | 有多少事实句挂了编号 | 100% 只代表"都挂了号"，不代表挂对了 |
| **答案支撑度** | 挂的号到底支不支持这句话 | 逐句和引用块比对，`grounded` 是整体分 |
| **拒答 / 低置信** | 库里到底有没有这个答案 | 拒答 = 不答；低置信 = 答但标黄 |

**覆盖率会骗人，支撑度不会。** 模型写「GPU 推理需要 A100[1]」，只要上下文里
存在 [1]，覆盖率就算它被支持——哪怕 [1] 讲的是节点调度。所以判断一个回答可不可信，
看支撑度那一栏，尤其看有没有「锚点缺失」：型号、版本、剂量这些具体事实如果在
引用块里找不到，就是模型拿通用知识补的。

支撑度低于阈值时回答会被标黄（`weak`），不是删掉——删掉等于替你做决定，
标黄把这个决定交回给你。

**答案怎么排，是渲染出来的，不是模型随便写的。** 站点对答案做了四层轻量排版：

- **引导句单独成行**：「具体操作步骤如下：」「注意事项：」这类带冒号的短句会被切成
  独立一段并加粗，后面带的步骤另起一段。原来它埋在长段落中间，读者找不到"这一段
  在讲哪一步"。汉字引导句 26 字封顶，超过就当成普通句子不切；「问：」「答：」这种
  一字引导也不切——那是对话录，切开像换了个人说话。
- **并列要点一条一行**：行首的 `1.` `2.` 解析成真正的有序列表，缩进和序号由浏览器
  按书写方向排（维吾尔语下序号在右、缩进也在右，不会跑到句末）。
- **连续引用合成区间牌**：一句话结尾挂着 `[1][2][3][4][5]` 时，页面显示的是一枚
  「1–5」而不是五个小方块；点它会把这条依据涉及的所有来源行一起点亮。编号不连续
  （`[1][3][7]`）不合并——那种情况说明依据分散，写成一个区间是撒谎。
- **写坏的记号自动还原**：模型偶尔把手写模板里的 n 一起抄出来（`[n1]`），收尾时
  会还原成 `[1]`，否则页面认不出引用、覆盖率算成 0、整篇看着像凭空写的。

排版的源头在提示词里（`config/prompts/qa_v1.md` 与 `qa_ug.md` 的「排版」段）：要求
模型把要点一条一行、引导句独占一行。改那一段等于改答案长什么样，改完旧会话不会变，
只影响新提的问题。

## 4. 参数：哪些能动，动了的后果

9 组 50 项，全部可以在界面改，**每个知识库一套独立值**。改完立刻生效（分块类除外）。

真正影响体验的只有五个：

| 参数 | 现值 | 动了会怎样 |
|---|---|---|
| `fusion.top_k` | 10 | 送精排的候选数。降 8 会掉分（第 9-10 名里真有答案），升 20 只慢不更好 |
| `rerank.enabled` | 开 | 关掉快 3 秒，文档级 top1 从 0.727 掉到 0.591 |
| `rerank.max_length` | 384 | 每条候选截多少字。512 更慢且更差（长窗口把 OCR 噪声算进相关性） |
| `rerank.timeout_s` | 8 | 超时即回退到融合顺序，打 `rerank_timeout` 标记 |
| `refusal.min_score` | 0.581 | 低于它就拒答。**必须标定，不要手填** |

### 库级参数是独立的一份

建库时复制一整套值，之后全局改了它也不跟。所以会出现「全局开着、这个库关着」——
状态栏会说明是哪一层关的。判断「这个库手调过没有」是拿它和**出厂值**比，
不是看键存不存在（库里存的是全量快照，键永远在）。

## 5. 标定：这两个阈值为什么不能用默认值

`refusal.min_score`（拒答）和 `support.threshold`（支撑度）是**这个嵌入模型 +
这批语料**的属性。换模型、换语料、甚至换问法，旧数字就作废。

```bash
# 服务要先跑起来——标定打的是真实检索链路，不是对着代码猜
cd ../model-eval
python calibrate.py --kb 2 --api http://127.0.0.1:8765 \
    --cases refusal_cases_wy.jsonl \
    --keep-support ../sky_agent/data/calibration/kb_2.json \
    --out ../sky_agent/data/calibration/kb_2.json
```

### 一定要用 `--cases`

不给 `--cases` 的话走留一法：屏蔽一篇文档，问「X 的临床表现有哪些」，不屏蔽能答、
屏蔽了不能答，由此造正负例。这个方法 AUC 能到 0.96，**但阈值会偏高**——因为造出来的
正例是把文档标题原样念一遍（「12.维吾尔医沙疗技术操作规范的临床表现有哪些」，余弦
0.80–0.85），而真实用户说的是「用热沙子把身子埋起来」，0.62–0.73。正例整体下移
0.08，阈值还架在旧位置，结果是 **36% 能答的问题被拒**。

`--cases` 用真实问题集（jsonl，一行一题）：

```jsonl
{"q": "同房以后出血，白带发黄还有味道", "truth": "4.宫颈肿（子宫颈炎）维吾尔医诊疗指南（修订稿）.pdf"}
{"q": "K8s 怎么部署 GPU 推理服务", "out_of_scope": true}
```

带 `truth` 是正例（库里能答），带 `out_of_scope` 是负例（库里没有）。负例要挑
**真正无关**的题，别把"库里没直接讲但沾边"的放进去——那会污染负例分布。

样本少于 50 条时标定结果会被标成不可信，程序退回出厂值。宁可说"没标定"，
也不用一个统计上站不住的数字替用户做决定。

### 当前结果（维医库，2026-11-06）

| 判据 | 阈值 | AUC | 误拒 | 漏拒 | 样本 |
|---|---|---|---|---|---|
| 拒答 | 0.581 | 1.000 | 0/30 | 0/22 | 52 |
| 支撑度（语义） | 0.665 | 0.992 | 4.3% | 4.3% | 96 |
| 支撑度（事实） | 靠锚点 | 0.514 | — | — | — |

事实层 AUC 0.514 不是失败报告：余弦对「300ml 改成 700ml」本来就近乎无感，
这一层靠字符串锚点兜底，两者分工不同。

## 6. 检索链路

```
问题
 ├─ 稠密召回   bge-small-zh 向量，取前 50          ~20ms
 ├─ 稀疏召回   jieba 分词 → FTS5 BM25，取前 50      ~30ms
 ├─ 加权融合   两路分数各自归一化后加权             <1ms
 ├─ 精排       前 10 条过 bge-reranker（CPU）      ~3s   ← 延迟大头
 └─ 引用装配   取前 5 条进 prompt，附编号
```

精排那 3 秒是算力决定的，不是代码慢：`2 × 278M 参数 × 384 token × 10 条 ≈ 2.1
TFLOPs`，8 核 Zen3 实测有效算力约 0.65 TFLOPS。想更快只能少算，而少算就是降质量。

## 8. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 提问只出引用、没有答案 | 生成后端没配 | 「模型服务」页加端点；状态栏第三行是红的 |
| `模型服务「xxx」不存在` | 库参数指向一个没配过的后端 | 加那个端点，或把本库的生成后端改成已配置的 |
| 精排显示「已关闭」 | 库参数里关了（全局可能开着） | 参数面板 → 检索 → 精排开关 |
| 第一次提问等 7 秒 | 精排没预热（预热开关被关过） | 重启服务，日志里找「精排模型就绪」 |
| 什么都拒 | 阈值是别的模型/语料标出来的 | 重跑标定，见 §5 |
| 答非所问但分数很高 | 见 §9 第一条 | 换更具体的问法 |
| 引用里混进不相关的古籍 | 见 §9 第二条 | 看支撑度，弱支撑的引用会标出来 |
| 改了参数没生效 | 分块类要重建索引；库参数是独立快照 | 看参数面板的「实际生效值」，不是「库内存值」 |
| 站点卡片说端口被占用 | 多半是**另开了一个后台**，同一个站点已经被它跑起来了 | 先看卡片是不是标成「外部托管」，见下面 |
| 手改 `config/models.yaml` 没生效 | 后台只在**启动时**读一次配置；界面里改的会写盘并即时生效 | 重启后台 |
| 状态栏「生成」红着说未选择 | 旧版库参数里存了一个空的 `generation.provider`，其实问答走的是全局后端 | 现在空值一律跟随全局，卡片会写「跟随全局：siliconflow」 |
| 答案只有两三行、张口就是「资料中未找到」 | 老提示词把"只能用资料"写成硬规矩，模型只能复述检索结果 | 已改口径：资料答不到就用模型自身知识把问题答完，不带 `[n]` 的句子就是通用知识；界面徽标仍标明来源 |
| 答案末尾总跟一句「总之／综上所述」 | 中文模型的收尾习惯，写"不要总结"反而会被原样念出来 | 后台在收尾时确定性剪掉纯总结句与检索报告句，不动带 `[n]` 的事实句 |

**「端口 8800 已被占用」但链接明明打得开。** 前台实例是后台进程里的一个线程，
不是独立进程：后台 A 把站点跑起来之后，后台 B（另一个端口上的 `knowtune serve`）
再去自动拉起同一个实例，必然撞端口——而 8800 上跑的就是**同一个站点**，链接是通
的。这种情况下卡片会标成「外部托管」并说出占用者的 PID，链接照用，但不给启停按钮，
因为句柄在 A 手里。两个后台同时开着本身就该改掉：

```bash
netstat -ano | findstr :8800     # 最后一列 PID 就是占着它的那个后台
```

关掉多余的那个后台（或直接在它页面上管站点）即可。注意别换端口绕：换了端口，
两个后台会各跑一份同名站点，日志和知识库缓存都变成两份。

诊断入口：右侧「检索测试」面板会把两路召回的原始排名、融合分、精排分全列出来，
是回答「为什么这段没被召回」的唯一工具。API 版：

```bash
curl -X POST localhost:8765/api/search/debug -H 'Content-Type: application/json' \
  -d '{"question":"沙疗的适应证","kb_id":2,"top_k":5}'
```

## 9. 已知限制

写在这里的都不是"小事化了"，是确实还没解决：

**1. 短而泛的问题会答错，而且系统不自知。**
「肚子疼」「头晕」这类问题，稠密余弦 0.60–0.62，和正常问题的分数区间重叠，
阈值分不开；分数最高的块来自《本草纲目》讲疮疡的段落。问法越具体越好：
「用热沙子埋身子治什么病」能答对，「肚子疼」不能。改进方向是查询改写或
领域词典扩展，两者都会引入新的延迟和新的错误，还没做。

**2. 古籍里的现代白话解读会"钓鱼"。**
语料里的古籍是带现代注释的版本，「与当代精准医学的理念不谋而合」「思考：你
认为……」这类段落对现代问题的字面吸引力极强。问「沙疗的适应证和禁忌证」，
精排把《脉经》排到第 2（0.936），因为它有一段专门讨论"适应证/禁忌证框架"。
这不是检索算法的问题，是语料没有区分原文与注解。

**3. 引用条数固定 5 条，不按相关度裁剪。**
第 3–5 条常常只有 0.54–0.62 分（噪声级），仍会进 prompt。裁剪规则需要真实
模型的生成质量来验证，本机没有可用后端，没敢盲改。

**4. 精排没有缓存。**
同一个问题问第二遍，3 秒照付。块在同一问题下的精排分是确定的，按
`chunk.content_hash + 问题哈希` 缓存可以直接省掉，还没做。

**5. 单机单用户。**
SQLite + 进程内模型，没有并发控制，多个人同时提问会互相排队（精排是单线程）。
要多人用得上服务化，那是另一个架构。

## 11. 本地模型（.gguf）：不联网也能出答案

云端 API 要密钥、要配额、要外网。本机有 `.gguf` 的话可以完全离线跑，代价是
慢一点、答得笨一点。

### 11.1 装 `llama-server`（只做一次）

```bash
python scripts/get_llama.py
```

脚本会挑对系统和后端，下完解压到 `tools/llama/`，程序立刻能找到它。
Windows 默认下 **Vulkan 版**：单包 35MB，直接吃显卡驱动，不用另装 CUDA 运行时
（CUDA 版要配 `cudart` 包，两个加起来 630MB，还要对应驱动版本）。

> 为什么有这么个脚本：`github.com` 的 release 下载在国内网络常被挡（实测这台机器
> 直连就是 `CONNECT 502`），但 `api.github.com` 通——所以「能查到版本号」不等于
> 「能下到文件」。脚本按镜像列表逐个试，并且**断点续传**：镜像不是连不上，是
> 下到一半断（实测 11.1/23.6 MB 处断开，还不报错）。只按 HTTP 200 判断成功，
> 拿到的是半个 zip，解压时才炸，报一个跟下载无关的「File is not a zip file」。

装好后「模型服务 → 扫描本地模型」这一行会从「没找到 llama-server（只能加进来，
起不了）」变成：

```
本地模型  4 个 .gguf · llama-server 就绪 · NVIDIA GeForce RTX 3060 Laptop GPU 6G（可用 5G）
```

有 GPU 就写卡名，没有就写「只有 CPU（出词会慢 5 倍以上）」。

### 11.2 起一个模型

「扫描本地模型」→ 每个 `.gguf` 右边点「加入」→ 卡片里点「启动」。启动要等权重
读进显存，7B 约 20 秒，期间按钮显示「启动中…」。起来后卡片显示端口与 ctx，
`http://127.0.0.1:8097/v1` 就是标准的 OpenAI 兼容地址。

一个模型一个进程一个端口，端口写在模型清单里，在 8090-8189 之间挑。同时起两个
模型就是两个进程两块显存——6G 卡只够一个 7B。

### 11.3 实测速度（RTX 3060 Laptop 6G，Qwen2.5-7B-Instruct Q4_K_M）

| 项 | 数值 |
|---|---|
| 加载 | 21 秒（从磁盘读 4.4GB 进显存） |
| prompt 处理 | 947 tok/s（3660 token 的 RAG 上下文约 3.9 秒） |
| 出词 | 27 tok/s（300 token 的答案约 11 秒） |
| 一次完整问答 | 22 秒 |
| 显存 | 5.5G / 6G |

对照云端 `deepseek-ai/DeepSeek-V4.1-Flash`：同样的库同样的问题，5 秒左右。
**本地 7B 的价值是离线和隐私，不是速度。** 想要接近云端的质量要 14B 以上，
那张卡装不下。

### 11.4 启动参数里的两个默认值

程序按下面这套参数起 `llama-server`，不需要你手写：

- `--parallel 1`：默认是 4 个并发槽，每槽各留一份 ctx 的 KV 缓存，7B 在
  4×4096 下光 KV 就吃 2G。本地是单人用，多出来的槽位只是把显存从权重手里拿走。
  *实测出词速度没变（27.8 → 27.0 tok/s）*——省下的显存被自动卸载放回了权重，
  瓶颈不在这。留着它是为了给更大的 ctx 腾地方。
- **不传 `-ngl`**：llama.cpp 会自己做显存拟合，有多少显存放多少层。手动写死
  `-ngl 99` 反而会关掉这个机制（日志里那句
  `failed to fit params to free device memory: n_gpu_layers already set by user to 99`
  就是在说这件事）。

ctx 默认 4096。RAG 的上下文（5 个块 + 提示词）大约 3600 token，够用；要喂更多
证据就在模型清单里改 `context`。7B 的 KV 每 4096 token 约 230MB。

### 11.5 切到本地生成

对话页顶部的后端下拉里选 `local`，或：

```bash
curl -X PATCH http://127.0.0.1:8765/api/kb/2/config \
  -H 'Content-Type: application/json' \
  -d '{"values":{"generation.provider":"local"}}'
```

### 11.6 起不来时看哪里

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 「没找到 llama-server」 | 二进制不在 `tools/llama`、PATH、`KNOWTUNE_LLAMA_SERVER` 里 | `python scripts/get_llama.py` |
| 启动后立刻退出 | 显存不够（看卡片旁的日志尾部） | 换更小的量化（Q4 以下）或更小的模型，或把 `context` 降到 2048 |
| 端口被占用 | 配置里写死的端口有别人在用，程序**不会**悄悄换一个 | 停掉占用者，或在清单里改 `port` |
| 进程显示「已停止」 | 服务重启过，子进程跟着没了 | 重新点启动 |
| 答得比云端笨 | 7B Q4 在中文长答上就是不如 DeepSeek | 本地是离线兜底，不是替代 |
