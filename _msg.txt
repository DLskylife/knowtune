模型选择模块重做：下拉平铺全部后端 + 全局当前=后端+模型 + 探测提示只说连通

用户三条反馈，对应三处真问题：

1) 「选不完模型」——对话页的生成模型下拉只列**当前后端**的候选。想用 B 后端
   上的某个模型，得先切后端、再切模型，而第二层还常是空的（探测缓存被清过）。
   - /api/models 新增 catalog：后端 × 模型的扁平表（合并探测缓存与人工清单）；
   - 对话页下拉按后端分组平铺全部模型，选哪个就自动带上哪个后端；
   - 末尾固定留「＋ 手动输入模型名…」：自建网关、内网代理、刚上线的新模型
     探测不出来时不能把人堵死。卡片下拉同样有这个口子。

2) 「模型全局做得不好」——全局当前其实是两段：哪个后端 + 这个后端的哪个模型。
   以前只能设后端，模型停在旧值上，改完发现"还是原来那个"。
   - POST /api/models/active 支持 {name, model}，模型名写回 models.yaml；
   - 模型页顶部新增「当前使用」条：后端下拉 / 模型下拉 / 状态 / 测试 / 编辑，
     一眼看到现在跑的是哪一套，两下就能改。

3) 「别每次说探测到一堆，我测哪个你说他连上就行」
   - probe_one 成功只返回「连通」（原来："就绪 · 对话验证通过 · 67 个可对话
     模型（另有 31 个图像/语音类已隐藏）"）；模型数量本来就在下拉里；
   - 单测 toast：「siliconflow 已连通」；批量：「3/5 连通」；
   - 卡片状态行：「连通 · 32ms」，不再复述统计。

顺手堵掉三个更深的坑（都会表现为"界面说能用、实际不能用"）：
- _key_fp 调 api_key() 没传后端名，而密钥是按名字存的 → 两边都算成 no_key、
  永远相等，探测缓存的密钥指纹整轮空转。测试全走 set_inline_key 刚好绕开。
- 盘上旧缓存的指纹本身就是 "no_key"，改好函数也拦不住 → 缓存加 __v，
  读到 v1 整批作废，让用户重测一次，好过拿假绿灯骗人。
- 首屏走 cached() 不读缓存文件，只有 probe_all 才加载 → 重启后模型页整页
  "还没探测"，而盘上明明有结论。启动时补 warm_cache()。

- 卡片：头部状态点 + 名字 + 本地/云 + 当前徽标 + 四个图标按钮（测/提示词/编辑/删），
  模型下拉与状态行、缺配置行；min-height + margin-top:auto 让同行按钮贴底对齐；
- 编辑/删除等被动操作从四个中文按钮收成图标，窄卡片不再换行参差；
- 卡片宽度 272→300，名字不再被挤成 "silico…"；
- 启动命令收进 <details>，默认折叠（这页原来一半高度是命令）；
- 「缺密钥：点编辑填 API Key」——原来那句带"只存内存、重启要重填"，每张卡念一遍；
- 不再一进站就弹「还没有可用的模型」：对话区本来就有引导卡，只在点发送时弹；
- mock 卡片的地址显示为"（不联网，只验证链路）"。
